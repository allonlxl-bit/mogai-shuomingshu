# 魔改复杂说明书成傻瓜式按步骤操作成你要的功能结果

[WorkBuddy 安装与使用](#在-workbuddy-里用) · [Codex 安装与使用](#在-codex-里用)

**让第一次拿起专业设备的人，也能用它完成一件自己在乎的事。**

这个开源项目想把熟手在设备旁手把手教人的经验留给下一个人。给出具体型号和想完成的事，制作者就能依照原厂资料，把分散在不同章节的知识排成实际操作顺序，在图上标出手该放哪里、眼睛该看哪里，并写清怎样判断做成了。相机、遥控器和专业软件都可以这样教。

一张操作卡值不值得分享，有个简单的检验办法：把它交给第一次用这台设备的人。编写者离开以后，他能不能照着做完，自己认出结果？

## 改前 / 改后：用富士 mini 12 拍 40 厘米处的小物

桌上有个小摆件，离镜头约 40 厘米。第一次用 mini 12 的人，拿起相机有两个疑问：镜头拧到哪一格？旁边的小灯还在闪，现在能拍吗？富士中文版第 9–10 页画了镜头环、拍摄距离和取景位置，第 12 页解释灯怎么闪，第 8 页讲相纸什么时候能取。拍一张照片，就用到了这几处。

操作卡把它们排回手上的动作顺序。**① 转**镜头环到机身印着的 `CLOSE-UP`，镜头前端离摆件约 40 厘米。**② 等**镜头上方的充电灯从慢闪变为常亮。**③ 拍**，从机背取景器把小圆圈对准摆件，按一次快门。等出片声停了，再捏住相纸边缘取出。下面的对比图可以直接对照富士原页和这三个操作位置。

## 这套方法还用在哪些项目里？

### 遥控攀爬车 · 一把遥控器换着控三台车

这套方法最早用在 Futaba 4PV 上。要解决的是几件开车前真会碰到的事：今天选的是哪台车？接收机怎么对频？孩子扣到底时，怎么限制前进油门？松开手轮，车还往一边偏，要调哪里？这些问题最后做成了 **26 页中文图解**。其中 Tekin BXR 电调的倒车速度单独用一页，既标出机壳上按哪个键、看哪组灯，也写了调完怎样架起车轮试方向。

后来换成触屏的 Futaba 7PXR，又做了一份 **17 页三车接线与操作图解**。每台车各有接线页，先找到对应接收机的插口，再进入这台车的模型档。对频结束还有一步：松开油门，轻转手轮，亲眼确认响应的是眼前这辆车。这两份定制手册的完整 PDF 保存在原项目中。

### 卡西欧 593 手表 · 从 10:58 调到 11:58

只想把小时往前拨一格，动手前要看清正在闪的是哪一位。操作卡先让读者在表背认准机芯编号，再用「秒数闪动 → 小时闪动」定位到该改的那一项。最后看小时从 10 变成 11，再退出调时，确认秒数继续走。[看四步调时卡](examples/watch-593/README.md)

### 标签预览器 · 把「工具箱」设成四张

这个随项目公开的软件示例把“输入了 4”和“已经保存”分成两个可见的瞬间。先选「工具箱」，输入 4，再点「保存并预览」。看到第四张标签后，切去「书架」再切回来，确认「工具箱」仍是四张。读者可以打开同一个预览器，照着三张圈注截图做一遍。[看带截图的操作步骤](examples/labels/README.md)

### 延伸场景 · 用单反拍清迎面跑来的孩子

家长到球场想拍清孩子的脸，未必知道手册里该查“连续自动对焦”。如果为这个任务做卡，先确认机身和镜头型号，以及家长习惯用取景器还是屏幕。然后用对应机型的图标出从哪里开启连续对焦、怎样把对焦区域放在孩子脸上、孩子跑近时怎样保持追焦。拍完还有一个检验动作：回放并放大眼睛，看清楚的是孩子，还是身后的球网。这是一个选题示例，具体按钮和取景器提示需按选定机型核对。

## 在 Codex 里用

安装方法见下方。新建对话后可以直接说：

> 用 $task-first-manual 给我做一份中文图解。我用的是［产品、型号或版本］，只想做［功能］。我最容易卡在［位置，如有］。我要［手机上看 / 一张打印卡 / 完整 PDF］。

## 安装到 Codex

下载或克隆本仓库。在 macOS 或 Linux 上，从仓库根目录执行以下命令。若同名技能已存在，命令会停下，供你比较版本。

```sh
skill_root="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$skill_root" &&
  mkdir "$skill_root/task-first-manual" &&
  cp -R skills/task-first-manual/. "$skill_root/task-first-manual/"
```

也可以手动把完整的 `skills/task-first-manual` 文件夹放进 Codex 的 `skills` 目录。新建对话后用 `$task-first-manual` 调用。其他支持 Markdown 指令的助手可以直接读取[技能入口](skills/task-first-manual/SKILL.md)，并保留旁边的 `references` 目录。

## 这套方法怎样决定写什么

|制作时先问|它会改变手册里的什么|
|---|---|
|读者最后想看到什么？|从目标倒推操作顺序，保留必需的前置条件。|
|手里到底是哪一款、哪一套？|先对车型、设备、账号或配置档逐一配对，再分配步骤。|
|读者的手和眼此刻在哪里？|图上圈具体位置，正文写手势和印字，下一行给可观察的反馈。|
|怎么知道保存了、连上了、真的起作用了？|分别写读回、连接和实际动作；涉及实体运行时标明待实测之处。|
|一页看得懂，为什么下一页卡住？|拿读者认可的一页作样本，逐步检查其余页面，再打开最终成品看图注与圈位。|
